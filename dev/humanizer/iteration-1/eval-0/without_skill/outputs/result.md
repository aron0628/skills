# 디지털 전환 현황 진단 및 실행 방향

## 요약

인프라는 옮겼으나 그 위에서 일하는 방식은 아직 옮기지 못했다. 클라우드 마이그레이션은 완료됐고 데이터 분석도 일부 의사결정 절차에 들어갔다. 반면 핵심 업무 시스템은 여전히 온프레미스에 남아 있고, 데이터를 다룰 인력과 품질 기준, 예산이 동시에 부족하다.

남은 과제 다섯 개는 서로 물려 있어 따로 풀면 각각 실패한다. 레거시를 걷어내도 데이터 품질 기준이 없으면 분석 결과를 의사결정에 쓸 수 없고, 엔지니어를 충원해도 부서가 데이터를 내놓지 않으면 투입할 과제가 없다.

따라서 개별 과제를 나열해 순차 개선하는 방식을 접고, 기술, 인력, 일하는 방식 세 축을 하나의 묶음으로 묶어 추진할 것을 제안한다. 경영진 결정이 필요한 사항은 4장에 정리했다.

## 2. 다섯 과제를 따로 풀 수 없는 이유

세 가지 연결이 실행 순서를 제약한다.

- 레거시를 현대화해도 품질 기준이 없으면 데이터는 여전히 신뢰받지 못한다. 시스템 교체 예산이 분석 성과로 연결되지 않는다.
- 인력을 충원해도 부서가 데이터를 내놓지 않으면 채용한 인원이 유휴 상태가 된다. 채용 실패가 아니라 순서 실패다.
- 예산은 나머지 네 과제의 상한선이다. 예산 결정이 미뤄지면 나머지는 논의만 진행된다.

즉 개별 과제의 우선순위를 다투는 문제가 아니라, 네 과제를 동시에 움직일 예산 규모를 먼저 정하는 문제다.

## 3. 실행 방향 세 축

### 3.1 기술 토대 재구축

레거시 시스템을 단계적으로 현대화해 기술 부채를 해소한다. 전면 재구축과 클라우드 네이티브 아키텍처 전환 중 하나를 선택해야 하며, 선택 기준은 시스템별 잔여 수명과 연계 건수다. 대상 시스템 목록과 전환 순서는 실행 계획에서 확정한다.

### 3.2 인적 역량 확보

외부 영입과 내부 육성을 병행한다. 외부 영입은 즉시 투입이 필요한 설계 역할, 내부 육성은 운영과 유지보수 역할로 구분한다. 교육은 실제 사내 데이터와 사내 과제를 쓰는 실무 과정으로 설계하고, 수료 인원이 아니라 담당 과제 수로 성과를 측정한다.

### 3.3 일하는 방식 전환

데이터 기반 의사결정을 정착시키는 조건은 경영진의 의지 표명과 반복 커뮤니케이션이다. 다만 선언만으로는 부서 간 공유가 바뀌지 않는다. 데이터셋별 소유 부서와 제공 의무를 명문화하고, 임원 보고 자료의 수치 출처를 공용 데이터로 한정하는 조치가 함께 필요하다.
