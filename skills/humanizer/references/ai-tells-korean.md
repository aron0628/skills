# 한국어 AI 티와 처방

`scan.py` 의 `[한국어 AI 티]` 항목이 여기 대응한다. 괄호 안 숫자는 실측 분리도다
(AI 코퍼스 대 사람 코퍼스 출현 밀도 비).

> **출처.** 이 파일의 패턴 분류와 실측 수치는 오픈소스 프로젝트
> **Humanize KR** (`github.com/epoko77-ai/im-not-ai`, MIT, 저자 epoko77-ai · Liam lee 외)
> 의 `ai-tell-taxonomy.md` v2.3 에서 가져왔다. 과윤문 가드(30%/50%), 역주입 금지,
> 전멸 금지 원칙도 그 프로젝트의 실사용 회차에서 검증된 것이다.
> 그 수치들의 원출처는 다시 KatFish(Park et al. — 인간 470편 대 LLM 1,624편),
> Toral(2019) post-editese, 한국 번역학계 번역투 연구(이영옥 2001 · 김정우 2007 ·
> 김도훈 2009 · 김혜영 2019 등)다. 재배포 시 이 고지를 유지할 것.

**먼저 읽을 것**: 이 목록은 제거 대상이지 생성 대상이 아니다. 글을 다시 쓰는 동안
여기 있는 표현을 **새로 심는 일이 실제로 일어난다.** 그래서 `scan.py --diff` 로
전후를 비교한다. 총량이 줄어도 늘어난 항목이 있으면 그 문장은 실패다.

## 표현을 걷어내는 것과 내용을 바꾸는 것

가장 흔한 사고는 빈 수사를 걷어내면서 그 자리에 없던 주장을 채우는 것이다.

- 원문: "이는 매우 중요한 성과라고 할 수 있습니다"
- 나쁜 수정: "이 성과로 영업이익률이 3%p 올랐다" — **원문에 없는 숫자를 만들었다**
- 좋은 수정: 그 문장을 삭제한다. 아무 정보가 없는 문장이므로 지우면 손실이 없다

빈 문장의 처방은 대개 **삭제**다. 대체가 아니다.

## S1 — 한 번만 나와도 티가 나는 것

### 연결어미 뒤 쉼표 (4.84배 — 단일 지표 최강)

한국어는 연결어미 자체가 호흡을 만들어 쉼표가 불필요하다. AI는 영어의
comma-after-conjunction 감각을 그대로 이식한다.

- `AI는 빠르게 발전하지만, 기업의 대응은 더디다` → `AI는 빠르게 발전하지만 기업의 대응은 더디다`
- `비용이 낮아지면서, 진입장벽이 사라졌다` → `비용이 낮아지면서 진입장벽이 사라졌다`
- `데이터를 정제하고, 모델을 학습시킨다` → `데이터를 정제하고 모델을 학습시킨다`

대상 어미: -고 -며 -지만 -면서 -아서 -어서 -는데 -거나 -든지

호흡이 너무 길어지면 쉼표를 지우는 대신 마침표로 끊는다. **다시 쓴 문장에 이 쉼표를
새로 넣지 않는다** — 실측에서 윤문 후 오히려 늘어난 사례가 있다(2→3, 4→7).

### 이중 피동

- `판단되어진다` → `판단된다` 또는 `판단한다`
- `개선되어질 것으로` → `개선될 것으로`
- `검토되어지고 있다` → `검토하고 있다`

### "가지고 있다" 직역

영어 have 의 기계적 대응이다. 한국어는 형용사나 이중주어로 쓴다.

- `강한 경쟁력을 가지고 있다` → `경쟁력이 강하다`
- `상당한 디지털 역량을 가지고 있습니다` → `디지털 역량이 이미 궤도에 올랐습니다`
- `세 가지 특징을 가진다` → `특징이 셋이다`

### 이모지·체크마크

비즈니스 문서에서 예외 없이 전부 삭제한다.

## S2 — 반복되면 티가 나는 것

### 부정 대구 (9.2배, 개인 블로그 대비 18배)

`A가 아니라 B` 계열. A~J 전체에서 실측 분리도가 가장 높은 축이다.

- `단순한 기술 도입이 아니라 기업 생존의 문제입니다`
- `단편적 개선이 아니라 구조적 전환입니다`
- `IT 부서만의 과제가 아니라 전사적 어젠다입니다`
- `~것이 아니라` / `~것은 아니다` / `~라기보다` 도 같은 수사

처방은 **하나만 남기고 나머지를 직접 단언으로** 푼다.
`단편적 개선이 아니라 구조적 전환입니다` → `구조를 바꿔야 합니다`

**전멸시키지 않는다.** 사람 글 532편 중 31편에 나오고, 한 칼럼에서 26회 쓴 필자도
있다. 판별의 결정타는 출현이 아니라 **연쇄 균일성** — 인접 문단이 같은 틀로만 굴러가는
것이다. 문서 전반에 흩어져 있고 사이에 다른 수사가 끼어 있으면 사람 글의 특징이므로
보존한다.

`A인가, B인가` 형태의 이항 대립 반복도 같은 카테고리다.

### 결산 상투구

`결론적으로` `이를 통해` `그러므로` `요약하면` `정리하자면` `종합하면`

합산 3회를 넘으면 1~2개만 남기고 지운다. 특히 마지막 문단을 `결론적으로` 로 시작하는
건 헤딩이 이미 `결론` 인 상황에서 중복이다.

`이를 통해 우리는 도약할 수 있을 것입니다` 는 정보가 0이다. 삭제한다.

### 의의 과장

`시사하는 바가 크다` `주목할 만하다` `매우 중요하다` `의미가 크다` `~라고 할 수 있습니다`

대개 삭제다. 무엇이 왜 중요한지를 쓸 수 있으면 쓰고, 쓸 수 없으면 그 문장은 없어도 된다.

### hype 어휘

`혁신적` `획기적` `압도적` `파격적` `폭발적` `전례 없는` `괄목할 만한`

수치로 환원한다. 환원할 수치가 원문에 없으면 형용사만 지운다.

### 번역투 조사 구문

| 걷어낼 것 | 바꿀 것 |
|---|---|
| ~를 통해 / ~를 통하여 | ~로, ~해서, ~함으로써 |
| ~에 있어(서) | ~에서, ~을 볼 때 |
| ~에 대해(서) | 목적격 조사로 직결 (`X에 대해 논의` → `X를 논의`) |
| ~와 관련하여 | ~에, ~의 |
| ~에 기반하여 | ~로, ~을 보고 |
| ~라는 점에서 | ~서, ~라는 이유로 |
| ~을 위해 | ~려고, ~도록 |
| ~에 의해 (피동) | 행위자를 주어로 (`AI에 의해 생성된` → `AI가 만든`) |
| ~에서의 / ~으로의 / ~에의 | 절로 풀어쓰기 |

**밀도 기준이다.** `~에 대해` 는 사람이 AI보다 3배 더 쓰고, `~를 통해` 도 비번역
한국어(84.4)가 번역문(42.1)보다 2배 자주 쓴다. 한 문단에 3회 이상 몰릴 때만 손댄다.
전량 치환하면 오히려 어색해진다.

### "~적 N" 추상 체인

`기술적 토대` `전략적 함의` `전사적 어젠다` `실천적 기반` `구조적 전환`

3회를 넘으면 명사+명사로 풀거나 구체 표현으로 바꾼다.
`기술적 토대의 재구축` → `기반 시스템 교체`

### 형식명사 분열문

`필요한 것은 ~이다` `중요한 것은 ~이다` `핵심은 ~이다` `문제는 ~이다` `~라는 점이다`

주어와 서술을 직결한다.
- `우리에게 필요한 것은 구조적 전환입니다` → `구조를 바꿔야 합니다`
- `주목할 점은 상호 연결되어 있다는 것입니다` → `이 과제들은 서로 맞물려 있습니다`

### 문두 접속사

`또한` `따라서` `즉` `나아가` `아울러` `게다가` `더욱이` `한편`

한 문단에 3회 이상 반복될 때 절반쯤 덜어낸다. 문서 단위 일괄 제거는 하지 않는다 —
사람 글의 밀도(0.43)와 일부 모델(0.26)이 구별되지 않아, 전량 제거하면 사람 글까지
훼손한다.

`즉` 은 문서당 2회 이하로 줄이고 `곧` `말하자면` 으로 변주하거나 생략한다.

### 결말 공식

`~할 때입니다` `~시점입니다` `~할 순간입니다` `지금이야말로`

구체 동사 단언으로 바꾼다. `지금이야말로 과감한 결단이 필요한 시점입니다` →
`1분기 안에 예산을 재배분해야 합니다`.

### "~할 수 있다" 반복

같은 형태가 4회 이상 반복돼 리듬을 지배할 때만 손댄다. 이때 **단정으로 바꾸지 않는다** —
`검토될 수 있습니다` 를 `검토합니다` 로 바꾸면 없던 확신이 생긴다. 형태만 흩는다
(`~할 여지가 있다` `~할 수도 있다`).

판별식은 SKILL.md 의 「헤지를 걷는 판별식」을 따른다.

### 수치 없는 강조

`상당히` `크게` `대폭` `현저히` `눈에 띄게` `비약적으로`

원문에 숫자가 있으면 숫자로 바꾼다. 없으면 강조어만 지운다 (숫자를 만들지 않는다).

## 리듬

- **문장 길이 변동계수 0.4 미만** — 다 같은 길이다. 짧은 문장 1~2개와 긴 문장 1개를
  문단마다 섞는다. 인접 문장을 이어 긴 문장을 만들되 **내용을 추가하지 않는다**.
- **동일 종결어미 4문장 연속** — 종결을 다양화한다.
- **쉼표 포함 문장 비율 50% 초과** — 일부를 마침표로 분할하거나 연결어미로 흡수한다.
  사람 평균은 26~33%다.
- **진행형 `~고 있다` 자동 매핑** — 단순 시제로 환원 가능하면 환원한다
  (`읽고 있다` → `읽는다`).

## 문서 서식

- **볼드 남용** — 실측: AI 문서 38.2회/1000어 대 사람 0.4회. 강조가 다섯 군데 있으면
  강조가 없는 것과 같다. 진짜 하나만 남긴다.
- **불릿 3블록 이상 연속** — 산문으로 녹인다. 나열이 정말 의미 있는 지점만 남긴다.
  다섯 항목 불릿은 대개 종합이 덜 된 것이다 (`mckinsey-voice.md` 「3개가 기본」).
- **헤딩 아래 안내문** — `이 섹션에서는 ~를 다룬다` 는 삭제한다.
- **도식적 헤딩** — `서론 / 본론 / 결론` 은 주장 헤딩으로 교체한다.
- **숫자 괄호 인덱싱** `1) 2) 3)` — 하나는 서술문으로 녹이고 나머지는 `우선` `다음으로`
  로 변주한다.

## 손대지 않는 것

- 학술·보고서의 실제 절 제목(`Ⅱ.`, `(3)`, 장 제목) — 콜론 포함 여부와 무관하게 보존
- 발화 표지가 붙은 직접 인용 (`~라고 말했다`, `~에 따르면`)
- 업계 표준 용어 — API, prompt, token, LLM 은 원어로. `prompt` → `지시문` 은 오역
- 원문에 이미 있던 구어·감탄·반문 — 사람 글의 증거다
- 경어체 등급 — 원문이 `합니다` 면 `합니다`, `한다` 면 `한다`. 올리지도 내리지도 않는다
